# Briefing

- Purpose: Public showcase of ~50 apps Claude Code built from `pisanuw/daily-project-ideas`, guided by Yusuf Pisan, and a lead source for paid custom builds (2026-11-02). Headline is "built by Claude"; the pitch is that guiding Claude to ship well is the skill on offer.
- Audience priority (owner, 2026-11-02): small businesses, then startups, then edtech, then universities. Connections and usefulness matter more than revenue.
- Promotion plan (2026-11-02): apps move to `<app>.pisan.me` subdomains; repo to be renamed; a `pisan-labs` GitHub org holds standalone mirrors of flagship apps, starting with bombe-bench and cache-miss-theater.
- Original scope (2026-05): Two shipped projects: `accessibility-lens` (WCAG 2.1 analyzer, TypeScript monorepo, Express + React, 107 tests) and `mult-streak` / `mult-streak-edge` (multiplication-streak game, 42 tests each, deployed to Render and Netlify respectively). Next project: find oldest un-implemented idea from the ideas repo and build it.
- Key decisions: Projects must have tests with good coverage (≥85% threshold), a documented `.env.example`, and be deployable to Netlify or Render. No interactive guidance — Claude owns delivery. Use `claude` CLI (not API key) for LLM calls in scripts. Conventional Commits enforced via `.git-hooks/commit-msg`. CI (`.github/workflows/ci.yml`) covers all three packages. Security: COOKIE_SECRET must be set in production (fail-closed); SSRF guard uses manual redirect following. Every deployed app gets one shared "built by" footer, injected into the built index.html at deploy time from scripts/site-footer.mjs (declarative shadow DOM, inherits page color); editing that file deploys nothing by itself; ship it with a manual Deploy run (`all` or named apps), since every Netlify deploy costs credits. ESLint flat config present in all packages.
- Non-goals: No manual guidance or approval loops during project construction; no monolithic single-app approach (each idea gets its own subdirectory).
- Weekly builds (owner, 2026-11-09): one substantial project per week instead of one small app per day. Fresh session each build day, state in `<slug>/HANDOFF.md`; up to 7 build days; ideas need two of five shape marks (stateful, connected, unattended, engine, shared) and a 5-to-7-milestone plan. Platform (docs/platform.md): the existing Supabase project `arktxlrlyceffyozdwhq` (shared with UpvoteMe and WCV Live Together, so every change is additive; shared tables in schema `platform`, one schema per app), sign-in by Google or magic link through Resend SMTP, an LLM gateway (Supabase Edge Function) with bring-your-own-key or the owner's key capped at $2/day, $10/week, $20/month per app and $0.25 per user per day, a daily usage email. Supabase admin runs through the "Supabase admin" GitHub Actions workflow with repo secrets; no session holds the tokens.
